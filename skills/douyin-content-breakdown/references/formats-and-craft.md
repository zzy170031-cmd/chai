# 抖音图文与短视频的创作设计

适用：判断表达形式、内容顺序、制作要求。以下 F 卡是创作设计建议，不是官方推荐规则或平台实验结果。来源状态为设计假设，必须结合原作品和目标受众检验；不规定统一时长、页数或字体大小。

## F01 图文：页序承担信息推进

- 观察：逐页记录主图、文字、该页新增信息、与前后页的关系，以及首图与标题是否兑现正文。把可见文字与OCR推测分开。
- 应用：首图给出明确对象和阅读收益；后续页按问题、证据、比较、过程或变化展开；末页交付答案、可保存的整理或有依据的问题。展示类可凭观察顺序成立，不必故意藏答案。
- 制作产物：`页码｜本页任务｜主视觉｜具体文案｜下一页增加什么｜素材条件`。建议页数按内容需要确定，不能反推原作真实页数。
- 反例：把视频旁白平均分到九张图，每张重复同一观点；为了翻页把关键条件藏到最后。两者都会破坏读者理解。
- 验证：实际手机显示尺寸下阅读，不放大能否识别主信息；读者能否复述结论及限制。没有后台页级数据时，不宣称滑动率或读完率提升。

## F02 短视频：变化组织时间

- 观察：区分人物行动、解释、展示与反应，每个节点新增什么信息；按实际读取范围记录镜头和字幕，不能只从抽帧推断连续剪辑效果。
- 应用：开头建立本片的观看承诺；中段围绕目标、问题或观察重点推进；结尾兑现。悬疑可延后答案，教程常适合先给结论或结果预览，空间展示可按整体到细节展开。
- 制作产物：`建议区间｜段落任务｜画面/动作｜具体对白或字幕｜声音任务｜结果/衔接｜素材`。建议区间是新作预算，不是原片测量或抖音门槛。
- 反例：为符合“每三秒反转”打断操作说明；没有看音轨就断言音乐提升留存。
- 验证：每段能说清保留理由；真实播放时检查对白、字幕、画面是否争抢注意，关掉声音也能否掌握必要信息。声音方案与原片已观察声音分列。

## F03 按观看任务选方法

| 任务 | 候选组织方式 | 不适用时换什么 |
|---|---|---|
| 剧情与人物 | 目标、限制、选择、代价、结果 | 无行动变化的纯展示，不强塞冲突 |
| 教程与解答 | 问题、条件、步骤、证据、例外 | 悬疑不要机械先揭底；给观看承诺即可 |
| 比较与测评 | 同条件、可比维度、差异、适用人群 | 条件不一致时保留差异，不造输赢 |
| 视觉与空间展示 | 整体、观察路线、关键细节、变化 | 需要解释机制时补局部标注，不只堆美图 |
| 经验与情绪表达 | 具体事件、处境、感受、获得的新理解 | 不把个人经验写成所有人的事实 |
| UGC参与 | 足够语境、作者示范、可选表达、真实反馈 | 没有共同题材或回收能力时仅作独立作品 |

## F04 价值与阅读负担

每一处字幕、效果、特写或翻页先回答“帮观众注意/理解什么”。长名词首次出现时用具体后果解释；背景文字与对白有冲突时择一承载。标题、封面、首图的承诺必须由内容兑现。不要把标题关键词堆积当作推荐模型的直接控制按钮。

图文的单页停留由观众决定，不能把视频完播阈值移植为图文门槛；视频的动态关系也不能仅凭若干静态图断定。发布尺寸、张数上限、音乐入口等产品规格只有在当次任务需要时查抖音当前官方界面/帮助，不从其他平台搬参数。
