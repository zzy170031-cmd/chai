# 按需调用的案例与方法

这些是创作分析候选，不是独立验证的爆款因果或官方算法规则。需要核对具体事件时读取本次用户提供的原件，不把方法概述当作案例事实。

## 结构候选

| 机制候选 | 分析重点 | 迁移要求 |
|---|---|---|
| 小起因与大后果 | 反差是否有完整因果，真正冲突是什么 | 保留因果与单位，不能通过编造金额或缺失背景误导。 |
| 网络关系进入现实 | 关系如何建立，具体付出如何兑现 | 用实际行动和证据承载情绪，不只换礼物名称。 |
| 成长与身份变化 | 起点、代价、选择和结果是否可见 | 前后变化需要可比证据。 |
| 困局与策略变化 | 目标、限制、决策和结果 | 让受众理解规则；图示与战报用于解释，不堆术语。 |
| 贡献与待遇不匹配 | 规则、投入和分配是否交代完整 | 保留影响判断的背景，不删掉反方事实煽动争论。 |
| 游戏行为映射日常 | 游戏机制与日常行为是否对应 | 迁移到新游戏前重查机制和语境。 |
| 实用解答 | 问题、条件、验证过程、例外 | 给出可执行结论，保留版本与资源条件。 |
| 角色拟人与关系改写 | 人物关系如何表达真实机制 | 保留角色与机制一致性，提示词不能代替故事。 |
| 参与选择 | 选项是否有实际收益和代价 | 问题与前文有关，观众有足够信息作判断。 |
| 视觉展示 | 画面本身带来什么观看价值 | 不强求冲突；辨认构图、尺度、细节、运动和声音的作用。 |

## 方法论整理

热点：来源与时间、受众关联、可用角度、素材成本、生命周期。历史榜单截图不当作当日热点。

账号定位：面向的人群、知识门槛、持续可产出的主题与内容收益。不要用“养号天数”替代内容定位。

字幕、音效、特效、表情包：具体信息任务、使用时刻、理解帮助及干扰成本。观众能否读清听清比堆效果更有意义。

发布与复盘：标题兑现、素材和事实完整、适用平台规则与实际数据。界面按钮位置和活动权益需当前核对。

## 资料质量

开头信息呈现：尽早让目标受众理解观看价值，但不统一规定字数、秒数或信息量；太多文字可能增加理解负担。提问与评论设计需有内容依据，疑问句本身不保证互动。音乐与口播的清晰度、节奏和语义应相互配合。

多栏并列表格不能按同一行拼成一个案例；同故事多版本不重复计为成功样本；播放与点赞不能混用；模板素材数不是镜头数。区服、金额、人物、脚本标题和正文不一致时，保留差异等待核对，不能静默统一为“正确版本”。
