# 本次创作上下文

用于下一条策划。只使用当前任务中用户已提供或明确指定读取的信息，不默认建立账号档案、长期受众画像或跨任务历史。不因缺少档案阻塞工作，不要求填写整套问卷。

## 最小信息

| 信息 | 如何使用 |
|---|---|
| 用户指定目标游戏或题材 | 决定策划人物、语境与内容关联；本次明确要求优先于旧资料 |
| 输出形式 | 沿用指定图文或短视频，不靠更换形式凑三条差异 |
| 本条表达 | 例如玩家口吻、说明型、幽默型；用户说明与观察假设分开 |
| 预期观看者 | 可依据用户定位设计，不从单个高赞视频推断年龄、性别等账号画像 |
| 观看收益与制作条件 | 本条希望观众得到什么；可用实录、角色素材、配音、人数和时间 |

同次请求存在互不兼容目标时，只问影响策划的缺口。目标游戏未知可继续拆原片，但不擅自选择游戏。受众或风格未知时，给明确标为策划假设的候选方向。用户提供旧资料只作本次参考，不静默加载其他账号或历史任务资料。

## 三条方案的选择依据

先把开头、发展、结尾及素材写到可制作程度，再为每条补一两句：适合当前哪些已知条件、主要素材门槛、什么情况下换另一条。条件足够时推荐优先项；不足时给条件排序，不伪造爆款概率或精确评分。

三个方向可在观看收益、视角、结构或参与方式上不同，不固定剧情/教程/UGC组合，只改标题或姓名不算差异。UGC需适合本条内容与任务，不为凑数加入。

## 隐私与使用边界

任务输出可以反馈可迁移方法，详见 [方法总结与复用](method-reuse.md)。默认不另存 profile、case、索引、JSON 台账，也不写全局助手记忆。用户明确要求保存时，仅保存指定对象到指定或明确的非公开项目位置；没有明确位置可先在当前回复交付，待位置明确再保存。

正常生成用户要求的 Excel 等交付物不等于授权建立账号档案或案例库。为当前任务核验而产生的必要证据遵循输出合同、只留必要内容，不将其转成可检索的个人历史；无法控制的宿主会话留存不宣称已删除或完全不留存。

这里借鉴的是按当前创作条件提供个性化建议的产品思路，不采用 Grocalo 增长自述或海外平台流量规则作为抖音依据。
