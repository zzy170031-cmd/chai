# 三类任务与交付

## 先选处理路径

以用户目的为准，不以参考文档标题中的“热点／爆款”决定类别。不要求用户每次重新填三选一；从请求和文档内容推断，只有确实影响交付而无法判断时才问。

| 模式 | 起点与核心问题 | 必须完成的工作 | 主要交付 |
|---|---|---|---|
| A 热门作品拆解与迁移 | 给具体作品，问它怎么成立、如何转为目标游戏创作 | 核对作品与范围，读取画面／声音／文字；按时间或页码细读；明确对白逐轮分析；提出有原片依据的迁移要求 | 原片拆解、创作指导、约三条下一条策划，按已确认篇幅展开 |
| B 时效热点联动 | 给现实事件／新技术／新品等，问现在怎样与游戏结合 | 联网核对事件及时间、实际素材、热度来源；找到可拍的游戏对应；检查制作周期是否赶得上话题窗口 | 热点核心与结合办法、视频指导、图文指导、低中高制作档位 |
| C 常态主题指导 | 给长期题材／游戏功能／玩家处境，问怎样持续做内容 | 研究主题受众价值、关系与场景、游戏承接；建立可持续的选题变化方式、完整示例和制作路径 | 创作总纲、方向库、视频指导、图文指导、素材与模板使用办法 |

热门作品不一定在实时热榜；长期受关注的题材也不等于已证实一直热门。A的作品可以提供B/C的参考，但仅放了案例链接不代表已经观看并验证。C可借与本主题有关的节日／版本节点或B的新闻作入口，母题仍独立成立；节点资料单独注明日期，不把全套常态指导改成追新闻。

三类共用：抖音平台边界、目标游戏、事实与演绎区分、原创要求、真实素材与隐私、[输出结构](output-contract.md)。腾讯表格只是交付位置，不能把三类流程合并成同一种四列表。

## 四层思考与多源融合

1. **事实与素材层**：提取用户目的、目标游戏、素材限制、参考格式和交付位置；核对实际能读取的内容、游戏事实与不确定处。A优先原作证据，B优先事件原始来源与时效，C优先主题长期观看价值与真实游戏场景。C不强制从当日热榜开始。
2. **选题层**：由已知事实与游戏素材推导多个可制作方向。每个方向说明“谁会关心、看什么、为何愿意继续、游戏怎样使内容发展、结果在哪里”，再选适合视频或图文的表达；不能由空泛关键词直接跳到脚本。
3. **制作指导层**：把方向转成创作要求、制作流程、具体内容要素、完整示例、素材与模板使用方法。指导句短而具体，完整对白／逐页文案保留在示例区，不靠长篇方法论代替可执行内容。
4. **交付层**：按用户给的表格布局、子表用途和读者使用顺序组织；单表变多表时跟随实际结构，不硬塞回旧表。各层可独立更新：换主题须重新推导选题，换格式只改表现形式，发现事实有误则重查所有依赖它的方向。

多份参考分别识别其用途：有的提供栏目骨架，有的提供创意／脚本，有的提供质量依据。可以融合结构和方法，不继承其他游戏的活动数字、未经核验的热度或主题特有规则。冲突以用户当前明确要求和可核事实处理；关键矛盾未解决时局部标明缺口，不把三份文档机械拼接，也不把来源作者的“已验证／必爆”自述当验证。

常态模式复用的是这套推导与交付方式，**不预置上一主题的人群、人物关系、专业、地域、功能、素材类型或题材方向**。每次从本次主题重新提炼；原参考只保留抽象结构，不把其私人正文和案例长期收录进技能。

## A：从原作证据转为制作需求

遵守主技能的完整／部分、策划篇幅确认与真实读取要求。每个关键迁移点对应原作时间／页码、具体做法、成立条件和游戏内替代。保留用户指出的核心梗、语气、前提与包袱触发关系；不能只复刻分镜表面。三案在观看收益、叙事组织或角色行动上有实质差异。有对话时原片逐轮、原创方案完整对白与画面动作并列。

默认Excel仍使用“创作指导／下一条策划／原片拆解”；腾讯表格写入用户指定的位置。用户同时要求视频、图文指导时各设一个子表，原片细拆按需求另表保留，不以排版删减。只要拆解时不强制出双形式、三档或三案。

完成标准：分析可回到原片核对，指出哪些可迁移、哪些不可迁移；新作属于目标游戏且能制作，不能用原创方案掩盖原片未读。

## B：从现实事件转为当下可制作的游戏内容

1. 核验事件主体、原始发布来源、发生日期与材料发布日期；区分实际展示、概念片、传闻、CG和网友二创。专业技术事实优先使用厂家／研究机构等一手来源，抖音热度只用实际取得的站内或官方证据。全网关注度不直接当抖音热榜排名。
2. 提取可以拿来创作的具体内容：动作轨迹、外形／尺度关系、现实用途、人物反应、认知反差。写清它与目标游戏的可见联系和不可混淆处，不为了蹭事件强行套名词。
3. 把联系做成可拍的桥接：相似动作卡点、尺度对照、用途替换、现实需求对照玩家处境等；这些是选项，不强制每次使用。真实参数需核来源；虚构变形／车辆雨等明确为脑洞，不能变成新品已实现能力或官方联动。
4. 视频与图文独立选方向：动态变形可服务视频，记录、需求对话、用途清单或前后对照可服务图文；不要求完全同题同叙事。每个方向按低中高给完整可做版本。
5. 标明素材可得性、授权条件、游戏版本和热点继续使用条件。事件失实、关键素材不可用、制作完成时话题已变化时，换经证实的角度或明确改为常态脑洞，不能继续称“今天热点”。

完成标准：观众能理解现实事件与游戏的关系，两者均有依据；至少有利用现成素材就能完成的低档方向；没有虚构实时热度和流量门槛。

## C：从长期主题构建持续创作指导

这类指南是供创作者反复选题、制作的手册，不是一条视频的分析，也不是一份日更热榜清单。先写清一句内容命题与观看收益，再建立下列层次，按资料规模分区，避免为了完整而空设栏目：

1. **创作总纲**：适用对象、游戏功能／玩法事实、内容命题、观众为什么在意、创作组合公式、必要边界。把项目要求与平台规则分开；单个项目的时长、占比、TAG不能推广为通用算法标准。
2. **主题怎样接入游戏**：`长期母题 → 人物关系／问题／观察对象 → 观众代入或获得 → 游戏内行动／可见变化 → 结果／情绪兑现`。先辨认该主题依靠故事、知识、关系、功能体验还是视觉展示成立，再选择合适路径，不强造人物冲突。
3. **方向库**：每个方向给观看理由、标题／首屏、内容如何发展、游戏画面怎么接、完整示例、素材与可变部分。同一主题的不同选题需要改变角色目标、信息、选择、观察角度或结果，不能只换专名和修饰词。剧情、知识解释、观察记录、对照、展示等表达可并存，不强制所有故事“争论后合作”。
4. **视频与图文分别展开**：视频按镜头／动作／对白及声音推进；图文按首图、逐页阅读关系、截图／示意图和可用文案推进。依照用户已确认的篇幅给完整内容；三图、六图、九图只能是候选结构，不能当统一准入条件。
5. **制作流程与质量要素**：从选题、素材匹配、粗排／粗剪，到可读性、声画关系、标题正文一致。获得感、惊喜感、表达力、感染力可作设计问题，不强制每条全部具备，不写成平台权重。低档先确保读得懂、能兑现，高档才增加制作复杂度；复杂特效不等于优质。
6. **素材与模板入口**：说明实际素材位置、能支持哪段、缺什么，不能把目录标题当已阅媒体。推荐模板时给适用情节、替换槽位、改编理由、所需画面与实际访问／试用状态。现成模板链接、参考成片、原创搭建说明分开；未打开剪映试用不能承诺可用。仅有模板链接不允许反推内容或音乐版权。
7. **持续变化办法**：区分不变的观看价值与每期需要改变的关键变量。给出几种下一期如何产生新问题、新决定或新结果的办法；每条有自己的完整结果。可写栏目示例与替换方法，不默认保存每次作品、玩家档案或长期跟踪记录，不自动设发布排期。

主题专属限制按本次内容确定，不能从旧主题全套继承。真实材料与自编剧情分开；功能截图只证明可见状态，不能推断未显示的资格、权益、能力或胜负。用户限制素材来源时尊重该范围；未限制时按主题选择录屏、截图、实拍、解说或其他可用材料，不把某次项目的聊天记录设为所有任务的必选素材。

完成标准：去掉“今天／最新热点”仍能解释观众为什么要看；创作者能从方向库选到一个可执行方案，并知道下一次怎样产生实质变化；游戏是内容发展的条件，不是尾部插片或背景贴图。

## 文档组织和共同质量检查

- A保持拆解证据和策划独立。B/C默认“视频创作建议／图文类创作建议”两张创作子表；大型主题指南可另设创作总纲、制作流程与要素、素材、模板导航。用户给的七表参考不等于每次必须七表，也不意味着允许删除其现有辅助表。要求只两表时把总纲／流程精简到各表开头与末尾，素材表照原约定保留。
- 内容层级是“先知道做什么 → 为什么这样做 → 看到完整示例 → 找到素材／模板 → 知道怎样改编”。导航链接有助于大指南，不用大标题和重复表头堆叠挤占内容。
- 每条检查：标题／首屏承诺是否兑现；信息是否容易读懂；具体游戏画面是否支持台词；视频的动作和声音／图文的阅读顺序是否服务主题；示例是否可执行；不同方向有无仅换名重复；当前事实是否核实。检查在内部完成，不追加对外验收或平台验证sheet。
- 参考指南中的“8秒以上、游戏占比40%、前3秒、固定标签数、字数／图数、BGM音量比例”等只作为该文档的项目要求或经验主张。复用前判断它是否仍被用户本次采用、是否具有现行官方依据；不能自动升级为抖音全平台规则。旧热榜、用户数量、学校人数、推荐星级也不能当成当前热度或爆款概率。
