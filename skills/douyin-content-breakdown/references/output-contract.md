# 输出与证据结构

先给作品结论与读取范围，再给足以支撑结论的片段；按复杂度压缩，避免无内容的固定栏目。

## 作品档案

来源链接／文件、标题、作者、类型、日期、时长／页数、分析日期。列出画面、文字、口播、音乐音效实际读取范围，未读取部分和原因。公开指标包含名称、原始显示值、采集时间；没有就留空。是否“爆款”单独标明依据或未验证。

## 内容结构与原理

| 时间或页码 | 观察与原句 | 段落任务 | 创作原理解释 | 证据／不确定处 |
|---|---|---|---|---|

表中观察不能含假装测量的数据。作品事实与创作者意图推测分开。

## 观众反应假设

| 具体设计及证据 | 可能的观众反应 | 平台来源或创作推断 | 所需验证数据 |
|---|---|---|---|

别把“可能愿意继续看”写成“留存提升”；没拿到后台数据就不能填完成率。即使拿到数据，也不能单凭相关性宣称唯一因果。

## 可迁移制作要求

明确原机制、成立条件、不变结构、可替换要素、适用边界。若用户有目标题材，输出对应节点／镜头任务、文案功能、素材、字幕和声音要求，以及如何验收。若用户仅要拆解，保持为复用说明，不扩大成成片生产。

## 下一条策划

用户要求下一条时默认约三个方案，用户明确数量优先。每个包含：名称、主要受众、观看收益、核心角度、具体开头、内容节点、结尾兑现、素材与制作条件、与原例的关系。至少在收益、组织、视角或参与方式上有实质区别；不能仅改标题、人物姓名或配色。默认保持指定的图文/短视频形式，不固定“剧情/教程/UGC”三件套。部分原作不可读时仍可给原创候选，但不得称为已验证从原作迁移。

图文给建议页序、每页主视觉和可用文案；短视频给镜头/动作、对白/字幕和声音任务。建议秒数/页数明确属于新作规划。数据或游戏机制未核实的位置给具体待补条件与替代写法，不捏造数值。连续剧也需交付本条的小结果；展示类结果可以是看清差异，无需剧情解决冲突。

## 对外Excel

用户要求Excel时，生成真实可打开的.xlsx，不把Markdown改扩展名。读取环境中可用的表格技能/工具规范；没有生成能力时如实报告。固定默认顺序：
1. `创作指导`：优先建议、原作依据、可迁移要求、适用条件。
2. `下一条策划`：先给约三个方案的差异概览，再逐个展开。以策划环节、具体内容、画面/制作要点三列为宜，重点是可制作内容，不是空白填写表。
3. `原片拆解`：图文用页码，视频用实际/近似时间及精度说明；观察与分析分列。

平台资料、原始指标、来源链、检查清单和验收记录另外保存到用户本地内部文件，不加入对外工作簿，也不隐藏在sheet、批注、元数据或外部链接中。仍需简短保留影响制作的重要限制，例如部分原片未读、示例虚构、具体机制待核验。文件中的事实不因移除来源sheet而失去内部出处映射。

默认不展示验收sheet或让验收抢占策划页；用户后续要求时再加入。检查完整单元格、文本换行、列宽、页/时间定位和三方案的实质差异。不要为文字分析强造评分或公式。内部证据索引不上传到公开仓库。工作簿仅由用户请求的案例生成，不将某一用户素材或私人路径作为skill模板。

末尾列出待补证据与最有价值的下一步；不以例行索要所有后台数据阻塞可完成的工作。

## 可选 JSON

```json
{
  "schema": "chai.breakdown.v1",
  "source": {"url": null, "file": null, "type": "unknown"},
  "coverage": {"status": "partial", "visual": [], "speech": [], "sound": [], "missing": []},
  "metrics": [],
  "segments": [],
  "hypotheses": [],
  "production_requirements": [],
  "next_concepts": [],
  "sources": []
}
```

`segments` 各项包含实际时间区间或页码、observation、principle、evidence、uncertainty；hypotheses 引用对应片段。覆盖区间采用秒数或页码，说明时间精度；读取完目录或抽样不等于完整覆盖。JSON 空数组表示待填，不表示零值或没有内容。
