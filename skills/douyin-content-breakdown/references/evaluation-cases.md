# 定向回归用例

维护者在修改方法路由、平台范围或输出合同时使用。下列为测试设计，不是已执行或通过声明。使用获准的真实输入运行，分别记录结构检查、受控情境回答、真实媒体读取与实际文件结果。不要用标题/关键词出现次数代替质量判断。

| 请求/输入 | 可观察的通过条件 | 失败条件 |
|---|---|---|
| 原片属于游戏A，用户指定给游戏B做策划 | 原片证据仍描述A；三案围绕B，说明结构迁移与B的具体关联、机制待核项 | 把原片误称B；把A的玩法套入B；仅改名称或输出泛题材 |
| 原片与目标均确认同一游戏 | 三案及后续建议保持该游戏；未确认目标时只询问缺口并继续拆片 | 因历史案例主动改成其他游戏或重复询问已确认目标 |
| 抖音多页图文，含可读首末页及中间页，要求三个同形式新作 | 所有可得页有覆盖记录；页序/主视觉/文案齐全，三案含义不同 | 编造原作秒数、声音或视频完播阈值；强改视频 |
| 抖音本地短视频，未取得音频理解，要求下一条 | 画面观察与声音新方案分开，三个节点完整的策划 | 宣称已经听懂BGM，或仅换标题 |
| 用户只要求图文拆解，不要新作 | 依据页序给结构与迁移要求，结束于所需范围 | 强出三案或UGC活动 |
| 给标题封面但无法读其余内容 | 部分读取，不捏造段落；原创候选与原作事实分开 | 用封面生成所谓完整原片拆解 |
| 用其他平台权重/流量阈值来优化抖音 | 不采纳该分发规则，回到抖音可核验范围与内容问题 | 将同集团或海外平台规则当抖音规则 |
| 给去年的抖音热点截图，要求今日热门策略 | 历史记录与当前判断分开；能给非热点替代 | 声称旧榜仍实时有效 |
| 要求低门槛共创，但没有可授权素材 | 提出原创可完成任务，区分评论与真正二创，记下素材条件 | 直接分发私人照片/未明音乐，虚构投稿 |
| 要求Excel、约三个策划示例、外部不展示验收 | 真实.xlsx三表正确顺序；策划完整可读；内部来源可回溯 | 假xlsx、仅空模板、隐藏来源sheet仍夹带、缺失限制被删除 |

每次记录：候选版本/差异、请求与输入、真实使用的工具、读取缺口、实际产物位置、失败及修复。未知数据不填零；未执行的用例保持未执行。对外文件检查与内部证据保留同时成立才算满足输出合同。
