# 腾讯表格交付与双形式创作指导

适用：将本技能产出的创作指导写入用户指定腾讯表格，或制作同结构的本地 Excel。这里只固定可复用工作方式，不保存用户文档地址、账户、Token、私人素材或逐次创作记录。

## 路由与授权

- 在创作指导任务中，明确作为输出位置提供的腾讯表格链接就是本次写入目标，沿用以下默认要求，不再逐项问字体、颜色、双子表和难度。用户当次明确要求优先。
- 区分作品链接、资料链接和交付链接。用户说“阅读／参考／先建议、不修改”时只读；仅丢来一个无上下文链接，先识别文档用途，不能自动覆盖。缺少选题／素材时先读表中现有任务和素材，只有仍无法确定的关键信息才询问。
- 保留原片范围、策划篇幅的确认规则：文档链接和默认排版不等于同意全片或压缩。纯热点创作指导没有待拆原片时，不强问原片时长；新作时长／页数可按方向建议，不冒充平台要求。
- 优先读取可用 `tencent-docs/SKILL.md`，在线表格用其 `sheet/entry.md` 与运行时 `sheet-mcp` 工具。Word、智能文档等链接按相应品类处理，不对非表格强套子表API；目标必须是双子表而链接不是表格时说明差异并确认输出位置。
- 通过 MCP 直接操作云端，不接管电脑、不以浏览器点击代替。认证沿用环境配置；不在聊天中索取或输出 Token，不写入本技能／仓库。MCP缺失或认证失效时报告具体阻塞；可先准备本地交付，不宣称已写入，也不静默安装、更换权限或改用桌面控制。

## 创作指导的内容结构

这是面向创作者选题与制作的指导，不默认使用“创作指导／下一条策划／原片拆解”三表。只做原作拆解时仍按原拆解合同；用户要完整逐轮拆解时不能为双表布局删掉该交付。

热点／常态指导默认两个创作子表：`视频创作建议`、`图文类创作建议`；有同义现成子表则原位更新，避免同名副本。完整常态指南还可按[三类任务](task-modes.md)组织总纲、流程与要素、素材和模板等辅助板块；用户要求只两表则嵌入相应表内，已有辅助表按用途保留。作品拆解保持原片证据交付，不用双表约定删掉用户要求的拆解。保留用户已有素材子表（不依赖它一定叫sheet3或排第三），不增设平台依据、验收、发布回填、评论归纳页。

每个子表先用简短总说明帮助选择方向，再按“核心方向 → 低／中／高制作档位”组织。通常使用四列：

`方向／档位｜创作内容与完整示例｜游戏结合点与素材｜制作方法与复用`

- 每个方向给选题切口、具体开头、创作公式、游戏关联、内容发展与结尾、实际素材位置及制作办法。公式可写“热点动作＋游戏内真实处境＋结果兑现＝爆款候选”，并说明这是创作组合，不保证流量，不虚构算法权重。
- 低档：可用现有录屏／截图、裁切、字幕、基础卡点或静态排版完成；必须是能执行的完整方案，不只是高档删特效。中档：增加定向录制、分镜／分层、对话组织或简单合成。高档：复杂匹配转场、跟踪、三维／AI或定制视觉；列清素材与技术前提，不把未试做工时写成保证。
- 视频给可直接采用的画面动作、剪辑顺序、字幕／声音任务；采用对话或口播时保留指导性概念，同时给连续完整原创台词。用户指定完整篇幅时遵守，不用概述代替。
- 图文独立设计首图承诺、逐页主视觉与可用文案、信息推进和末页兑现。页数随内容需要，不把镜头秒数、音效或运镜照搬为静态页动作。视频与图文可以采用不同方向，不为了对应而做同一套示例。
- 每档必须落到目标游戏的角色处境、可核玩法／术语、可取得画面与行动结果。不能只加游戏名；不能借EVE等作品的机制补齐星际猎人素材缺口。目标沿用本任务已确认值，不擅自更换游戏；未确认时按主技能规则处理。
- 低成本方案可以推荐剪映的手工搭建步骤和素材槽位；没有生成、导入实测的草稿／模板包，只能称“搭建说明”，不能称一键可用模板。不操作剪映。

## 读取、准备、写入、核对

1. 识别目标文档和各子表ID。完整读取拟修改的创作子表与用户指定素材子表的有效内容，包含格式、合并范围、超链接；较大范围分块读取并核对覆盖。多列并排板块可能在E列或更右侧，不能只读前几列；有效区域未知时按已知网格分块核查。其他子表先识别用途，未经要求不改。对同名子表用ID确认，不能只凭顺序。
2. 素材子表中的链接按用途读取必要关联资料，清楚区分正文已读、仅见目录／文件名、媒体已看与媒体不可访问。链接单元格返回空不等于附件不存在；使用工具支持的链接／对象信息核对，必要时格式化导出核查。不能声称读完所有外链或看过只有文件名的视频。
3. 在写入前组织好完整内容及精确写入范围，检查方向差异、三档可行性、游戏对应和事实限制。沿用用户已有参考的栏目与用语，只在本次授权范围内改写。现有他人补充、素材、附件、链接和无关子表保留；出现并发改动时先重读差异。
4. 合并区域先读取，需重排时逐个按确切范围解除，避免整表清空。使用批量写入；缩短旧内容时明确清理获准替换范围内的尾部残留，不能假定CSV的空字段会清除旧值。重试前读取已应用状态，避免重复加表或重复追加。
5. 设置下述样式并恢复必要超链接。按运行时参数声明调用，遇到类型错误查对应API说明；不要硬编码过时的参数形式。少量可诊断失败可修正后重试，权限／认证错误停止相关写入并报告已完成范围。
6. 写后回读全部改动单元格，与拟写内容逐项比较，查遗漏、错位、旧尾行、丢失链接；核对字体、色块、列宽、行高和冻结请求结果。可通过文档导出进行文件检查，但不绕过用户的MCP操作边界。API回读证明内容／样式，不能冒充已完成屏幕视觉验收。完成时返回文档链接、修改子表和实际验证情况。

## 默认排版

- 全部字体使用微软雅黑。原表局部更新时只处理获准的表与范围；用户明确要求全工作簿统一字体时才覆盖其他子表。
- 标题浅底深字、建议16号，正文建议11号；分区标题约12号，不使用大片重色压住正文。字号和行高随实际阅读效果调整。
- 低档整行浅绿 `#E8F3EA`，中档浅蓝 `#E8F0FC`，高档浅橙 `#FFEEDF`；同时保留“低／中／高”文字，不能只依靠颜色。表头可用淡蓝灰，正文深色保证对比度。需要ARGB时补不透明前缀FF。
- 列宽按内容分配，主体内容列最宽；长文换行、顶端对齐，行高按实际文案调节，避免固定高度截字。方向标题和短说明可适度合并，不把所有正文并成大格。
- **首行默认不冻结；不要因此取消全部冻结。** 保留既有列冻结，新表可冻结首列帮助横向对照。腾讯表格冻结行从顶部连续计算，无法既放开首行又单独冻结第4行；此时冻结行数设0、列数按需保留。仅修改行冻结时不擅改列配置；若API要求同时传入，先取得原列配置。标题跨冻结边界时可调整标题摆放，不能擅自取消用户允许的列冻结。
- 这些是交付默认值，不是抖音流量规则。用户本次明确的参考格式或新要求优先。
